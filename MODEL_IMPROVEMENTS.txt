✓ PROBLEMA IDENTIFICADO:
  - El modelo anterior estimaba IDENTICO para todas las historias
  - Causa: Feature engineering muy simplista (solo 3 features con valores por defecto)
  - Las historias sin priority/issue_type usaban valores por defecto (0.5, 0.5)

✓ SOLUCIÓN IMPLEMENTADA:

  1. FEATURE ENGINEERING MEJORADO (10 Features)
     - Complejidad: Detecta keywords técnicos (integración, refactor, seguridad)
     - Alcance: Longitud de descripción normalizada
     - Criterios: Número de criterios de aceptación
     - Palabras técnicas: UI, backend, integración presentes
     - Integración: APIs y sistemas externos
     - Testing: Requisitos de testing y QA
     - Prioridad: Urgencia detectada en el título
     - Tipo de issue: Feature/Bug/Task heurístico
     - Números: Cantidad de números en la descripción
     - Variedad: Ratio de palabras únicas

  2. DATOS DE ENTRENAMIENTO MEJORADOS (150 muestras)
     - 5 tipos de historias diferentes:
       * Simple UI (baja complejidad)
       * Complex Backend (alta complejidad)
       * Integration (alta complejidad)
       * Bug Fix (baja complejidad)
       * Testing (media complejidad)
     - Variación realista en targets:
       * Story Points: 5-13 (avg: 9.6)
       * Duración: 1.6-8.8 días (avg: 5.3)
       * Costo: $225-$1805 (avg: $1072)
       * Esfuerzo: 46.6-197.1h (avg: 120.2)
